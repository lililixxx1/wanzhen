## 执行裁决记录（主会话派工时定稿，2026-10-04）

- **选型 = 选项 B**：手写 `std::thread` 持久线程池（零新依赖）。sim 保持 headless 零
  bevy 依赖（AGENTS.md 架构：渲染栈归独立 crate render-spike）；bevy_ecs 调度器系统
  执行序不保证确定、确定性面无法数学证明与 5.2 纪律兼容；线程档位与分片边界需完全
  自控；避开 bevy 编译内存负担（cargo -j 3 纪律）。
- **分片边界规则 = 连续均摊分块**：片 k ∈ [0,T) 的范围 = `[k*n/T, (k+1)*n/T)`
  （整数除法，片长差 ≤ 1）。纯执行划分（意图计算 per-i 无共享写）⇒ 分片方式与结果
  无关；连续块 cache 友好。
- **验收 4 口径调整（留痕，含执行期再修正）**：朴素 O(N²) 下 10k×14400
  ticks@12 线程的内存带宽量级推算 ≈ 300s+（每 tick 2 遍 × 10⁸ 单位访问 × 32B
  stride ≈ 6.4GB 内存流 / L3 ~300GB/s ≈ 21ms/tick 下限 × 14400）——「60s 超时
  保护」在 T006 范围内（任务卡明文排除性能调优）物理不可达。调整为**防死锁
  兜底语义**：看门狗超时 + 不 panic + 无死锁断言，实测时长如实入证据档。
  派工时初定看门狗 600s；执行期首跑实测 10k@12 线程 ≈ 52ms/tick × 14400 ≈
  750s（矩阵 10k 局 300 ticks=15.6s 外推）超出 600s 看门狗（首跑 exit 124
  留痕）——**再修正为 1800s**（≈2.4× 最坏正常时长余量）。「60s 内跑完」
  转为 T007 性能输入（空间划分 / 数据布局优化方向）。
- **对拍矩阵口径**：16 局 = 规模 {1k（每方 500）, 10k（每方 5000）} × 线程
