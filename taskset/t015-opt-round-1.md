## 背景（T007 实测，docs/evidence/t007/summary.md）

- 止损 TRIPPED：4/4 采样点单线程 µs > 2µs（4.012/19.847/41.010/200.626，
  1k/5k/10k/50k）——朴素 O(N²) 索敌主导（R²=1.000000 的 C(N)=aN+bN² 拟合）。
- 加速比侧健康：12 线程 7.22×/16 外推 9.42× @10k——瓶颈在算法复杂度不在并行。
- 缺口：常态万人达标需 µs ≤ 5.78（= 8ms×7.22÷10000），现 41.01 → 需 ~7.1×
  成本削减；极限十万需 ~178×（仅算法级可达）。

## 设计裁决（2026-10-05 开工定稿，主会话；「范围内」候选方向的收敛与等价性论证）

- **D1 策略**：move/combat 两个意图阶段从 O(N²) 全量对扫降为「(x, 索引) 全序
  排序 + O(1) 邻域查询 + O(N) 双向扫掠」；apply 阶段（索引序串行语义）、
  state_hash、retain、cd、combat 重索敌**零改动**。新增 `sim/src/spatial.rs`
  私有辅助模块；旧 `move_intent_chunk` / `combat_intent_chunk` **逐字保留**
  （回退路径 + 语义参照实现）。
- **D2 快路径准入（eligibility）**：每意图阶段建序后一遍 O(N) 检查 =「x 沿
  order 严格递增（无平局）**且** alive 全真」；不满足 → 回退旧 O(N²) 路径。
  退化域（World::new 重合占位 / 含同 x 手构局）走回退 = 行为与优化前逐字一致。
- **D3 排序确定性**：order 按 (x[i], i) 全序排列——索引互异 ⇒ 比较器为全序 ⇒
  排序结果**唯一**，与算法稳定性 / 线程数无关。threads=1 单次 sort_unstable；
  pool 路径 map_chunks 分片排序 + 串行自底向上两两归并（同一唯一全序）。
- **D4 move 快路径查询**（等价推导）：x 互异 ⇒ 严格前方最近者 = 序中紧邻——
  红 front(i)=order[pos[i]+1]、蓝 = order[pos[i]−1]（无 dir 算术，结构邻接，
  T006 方向感知教训零暴露面）；apply 阶段 clamp 公式不动（world.rs 既有式）。
- **D5 combat 快路径查询**：两遍 O(N) 扫掠（L→R / R→L 各携带最近敌位置）得
  每位置最近左右敌；per-unit 比较 (dL,uL) vs (dR,uR)：距离小者胜、**平局取
  小单位索引**——与旧「索引序扫描 d<best 严格小于 ⇒ 首个（最小索引）胜」
  等价（x 互异 ⇒ 同距离敌至多左右各一）。in_range 现算同式（半径和 +
  MELEE_MARGIN_Q32 闭区间）。
- **D6 combat apply 重索敌不动**：仅快照目标同 tick 先死时触发的 O(N) 现扫，
  频率低且 T007 四配置均为纯移动段不触达；残项留 t016 菜单。
- **D7 并行结构**：仅「分片排序」与「意图查询」经 pool map_chunks（沿用
  T006 Arc 快照模式，f 不 panic 契约）；归并 / 扫掠 / eligibility / apply /
  hash 串行。threads=1 与多线程同一意图纯函数 ⇒ 与线程数无关（T006 D2 原则）。
- **D8 等价性证据链（红线落地）**：①既有单测零改动全绿；②T002/T004 黄金锚
  CLI 复现 + --battle 交叉；③新增 differential 单测（固定种子随机 x 互异局，
  旧 chunk 函数 vs 快路径逐单位对拍 front/target/in_range）；④T008 对拍矩阵
  全 29 局复跑 vs 归档逐字节 diff（优化后全矩阵分钟级，战斗段含内）；⑤bench
  四配置 final_hash 与 T007 summary.md 附录 A 一致。
- **D9 复测口径**：T007 bench 套件原样复用（16 配置 = 1k×600t/5k×300t/
  10k×300t/50k×30t × threads{1,3,6,12} × seed 42 + `--summarize` 判定行代码
  生成）；证据档 docs/evidence/t015/（口径/环境档/双窗口空闲预检同 t007）。
- **D10 预注册预期（开工登记，防事后合理化）**：
  - ① µs 四点全部大幅下移，预估区间 0.08~0.4 µs（Amdahl+常数估算）→ 判定
    预期 **PASS**（≤2µs）；任一点 >2µs = 实现常数失控，异常上报。
  - ② @10k 加速比：**预期结构性下移至 ≈1.5~2.5×，判定预期 TRIPPED**。机理
    （预注册）：删除占总耗时 ~97% 的可并行 O(N²) 扫描后，每 tick 剩余成本由
    串行 FNV-1a 哈希链（hash.rs 逐字节依赖链 19B/单位，@10k ≈0.2ms）+ 语义
    必串行的 apply/retain（索引序 clamp/墓碑语义）+ 串行归并/扫掠主导；即便
    其余全部完美并行 S(12)@10k 上限 ≈3~4×（hash 占比 ~19% 时恰在 4× 边界），
    现实设计 ≈1.5~2.5×。⇒ **缺口数字如实入档 + Amdahl 分解留痕**；轮二无法
    以诚实手段闭合（并行归并/扫掠残项 ≤+0.5×）——owner 决策点：修订 ② 口径
    或接受披露跳过轮二。本卡只产数据与判定，不自行放行。
  - 加速比随 N 上升（可并行排序占比更大）：50k 档预期 ≈2~3.5×。
  - ③ 外推十万 / ⑥ 内存非本卡判定项，summarize 原样输出（③ 预期大幅改善；
    ⑥ 无内存行为变更不重跑长跑，reviewer 可要求加样）。
- **D11 时间盒与停点**：≤2 工作日（2026-10-05 开工计）；①四点全 ≤2µs 即
  性能侧收工（② 按 D10 披露）；任何哈希漂移 = 立即停 + 修复（等价性优先于
  性能）；一轮达标即停，不开无限优化轮。
